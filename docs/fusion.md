## 为什么采用这一结构

现有本机服务统一处理连接、请求执行、素材和持久化，能保住原生多模态链路与已有记录。PrismLab 的发现与解释方式接入真实目录；新 Gemini 操作使用同一预览、执行、事件和保存链路。性能引擎由本机 Node 服务启动无界面 Python 子进程，通过标准输入传递最小配置与鉴权，复用原有 Python 调度/统计函数，没有另写一个近似的 JavaScript 压测器。

原 `llm-bench` 源码完整保留，网页直接支持其核心无界面场景。双窗口 GUI 可按上游文档独立启动；主应用无需它的 NiceGUI/pywebview 依赖。精确 Token 预跑会产生额外真实调用，本轮没有自动执行；原上游 CLI/GUI 的估算功能仍在。网页不承诺跨原生多模态接口的统一压测。

## 核查后没有继承的行为

PrismLab 的 `App.tsx` 含预置成功记录；部分工作台初始 state 含固定耗时和费用。其 `server.ts` 的部分任务使用内存模拟状态、预设视频或网格；部分请求虽调用 Google，却通过固定比例计算 TTFT，或合成 Logprobs/缓存与用量。A/B 页还存在错误时延/费用兜底。这些不能当作真实实验证据，没有进入新数据库、图表、目录状态或报告。

相关能力用当前项目真实适配替代：视频/3D 通过现有异步任务追踪与产物保存；工具/向量通过现有工作台；Gemini 通过独立原生适配。尚未支持的厂商和操作继续显示文档或线索状态。没有让一个厂商的成功调用冒充另一个厂商的能力。

## 验证与使用限制

- 原生目录、类型、构建、适配器、导入、后端与新增融合/评测回归组成 `npm run check`。测试数据使用临时数据库和回环 HTTP/WS/本地响应样本，不操作已有账户。
- Gemini 使用核对后的官方 REST 字段，状态为 `documented`；自动样本覆盖不等于真实账户通过。范围与来源见 [Gemini 说明](gemini-coverage.md)。
- 评测强制费用确认，设有逻辑请求、HTTP 尝试、并发、时长、响应及导入大小限制；停止、服务重启不自动重发。已到上游的调用可能继续计费。
- 凭证不进入子进程参数或报告；报告与导入保持脱敏，CSV 对公式起始字符作转义。配置的代理使用本机已有规则，目标地址核验后固定，重定向不会携带凭证继续请求。
- 本轮没有新增付费调用、负载压测或公网部署。此前文本实测证据保留，新的端点/账户权限与真实体验需用户亲测。

操作验收见 [手工验收](manual-test.md)，工程检查结果见 [验证记录](verification.md)。
